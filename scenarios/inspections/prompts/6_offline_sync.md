# Offline sync

Field workers often inspect sites without connectivity. The tablet app keeps a copy of every form
version it has downloaded, collects submissions offline, and uploads them once it's back online:
sometimes days later, after the form has been edited, and sometimes more than once when an upload
was interrupted.

## 1. Submitting against a specific version
- Submissions may include `formVersion`. The submission is then validated against that version,
  stored as belonging to it, and rendered and filtered with it, even if newer versions exist.
- Without `formVersion`, the latest version applies, as today.
- A `formVersion` that doesn't exist for the form is rejected with `400`.

## 2. Safe retries
- Submissions may include `clientSubmissionId`, a string generated by the tablet. It is returned
  with the submission.
- If a submission with the same `clientSubmissionId` was already stored for the same form, and the
  new request has the same content, respond `200` with the stored submission instead of creating a
  duplicate. This must also hold when retries arrive at the same time.
- If the same `clientSubmissionId` arrives with different content, respond `409` and keep the
  stored submission unchanged.

## 3. Batch upload
`POST /submissions/batch`
```json
{
  "submissions": [
    { "formId": "…", "formVersion": 2, "clientSubmissionId": "tab-17-000123",
      "submittedBy": "worker-17", "submittedAt": "2026-11-20T08:12:00Z", "answers": { … } },
    …
  ]
}
```
- Up to 200 entries. Each entry is handled exactly like `POST /forms/:formId/submissions` with its
  own `formId`, and independently: an invalid entry doesn't stop the others.
- Returns `200` with `{ "results": [ … ] }`, one result per entry in the same order:
  `{ "status": 201, "submission": { … } }` for a new submission, `{ "status": 200, "submission": { … } }`
  for a retry, and `{ "status": 400 | 404 | 409, "error": "…" }` for a rejected entry (`404` if the
  form doesn't exist).
- Entries in the same batch with the same `formId` and `clientSubmissionId` are treated like
  retries: the first is stored, the later ones return it.
